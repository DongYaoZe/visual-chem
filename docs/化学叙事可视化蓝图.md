## 第一部分：调研报告——市面现状

全球"大学化学教育可视化"生态可以归纳为**三条互不交汇的脉络**。理解这三条脉络各自的成熟度与缺陷，是本项目定位的全部依据。

### 脉络一：化学教学可视化资源库（成熟，但形态传统）

| 项目 | 定位 | 技术/形态 | 采用情况 | 许可 |
|---|---|---|---|---|
| **ChemTube3D**（利物浦大学，2008–） | A-level 与本科化学的 3D 动画 OER，有机反应机理见长 | 网页 3D 动画 + 分子结构 | 2017 年约 70 万用户、近 200 万页面浏览、覆盖 217 国（校方 Google Analytics 自报）[1] | 当前页脚为 CC BY-NC-SA 2.0 UK：不可商用，改编须以相同许可共享 |
| **PhET**（科罗拉多大学） | 开放沙盒式理科模拟的鼻祖，交互文章谱系公认的源头之一 [6] | HTML5 模拟 | 全球广泛使用（本轮调研未获一手确证数据） | 开源 |
| **OSSCAR**（EPFL，2024 论文） | 计算物理/化学教学的 Jupyter 组件族：布里渊区、元素周期表、能带、分子轨道 | ipywidgets / JupyterLab 扩展，github.com/osscar-org | 同行评审发表于 Comput. Phys. Commun. 305, 109353 (2024) [2] | 开源 |
| **LearnChemE**（CU Boulder，Falconer 主持） | 化工热力学教学法最成体系的范例：**40+ 个交互模拟 + screencast 屏幕讲解 + 1175+ 道 ConcepTest 概念题**三位一体 [5] | Mathematica（部分已迁移网页） | 2016 年发表于 Chemical Engineering Education，模式持续扩张至今 [5] | 免费使用 |
| **JSmol 3D 相图**（Glasser/Herráez/Hanson, *J. Chem. Educ.* 2009, 86, 566） | 把分子可视化工具改造成交互式 3D pVT 相图（水、CO₂、氨），可旋转、2D 投影、相变曲线高亮 | Jmol → JSmol/HTML5，至今在线 [4] | 化学教育界"轻量相图交互"方向的早期代表 | 开源 |

**关键观察**：这一脉络的所有项目都是"**模拟/资源的集合**"——学生自己点开某个模拟、自己摸索。LearnChemE 意识到了这个问题，所以给每个模拟配 screencast 和概念题，但那仍是"模拟 + 外挂讲解"，不是一体化的叙事。

### 脉络二：相图/热力学专业计算（专业工具强大，教学端零碎）

- **商业黑箱**：Thermo-Calc、FactSage 是工业标准，但闭源、昂贵、完全不面向教学。
- **pycalphad**（MIT 许可）是开源侧的重要参照：符号化热力学模型、与 Gibbs 能最小化求解器解耦、运行时可编程覆盖，2026 年仍活跃维护（v0.11.2）[3]。第二轮核验发现其当前仍有 Cython/SymEngine 原生依赖且没有可直接使用的 WASM wheel，因此只作为远期 TDB/一般 CALPHAD 路线，第一季不进入关键路径。
- **OpenCalphad**（Bo Sundman，Fortran）：数据库格式与 Thermo-Calc TDB 兼容。
- 教学端的努力**持续但分散**：Viana 2025 的教学用 Python 相平衡代码（Wiley, *Comput. Appl. Eng. Educ.*）[4]、MIT AY2023 校友基金资助的 Phase Diagram Explorer（目标：凸包构造"快到能课堂实时交互"）[4]、2009 年的 JSmol 相图 [4]。三十年里不断有人重复做"课堂相图小工具"，**却没有一个长成平台**。

**关键观察**：专业计算与教学可视化之间存在断层。你的 visual-chem 已经站在这个断层上正确的一侧——热力学是真算的（Antoine + Margules + 熔度方程数值求根），不是贴图。

### 脉络三：叙事式/可解释科学可视化（方法论已成熟，但从未系统性进入化学）

这是调研中最有战略价值的发现。

- **Distill.pub 的理论总结**（同行评审，DOI 10.23915/distill.00028）：基于 60+ 篇交互文章的语料分析，交互式文章有五大效用——**连接人与数据、使系统可玩、促进自我反思、个性化阅读、降低认知负荷**；交互文章已被证明比静态媒介更吸引人、更利于记忆与学习 [6]。
- **Bartosz Ciechanowski（ciechanow.ski）的叙事模式**：与 PhET 的"开放沙盒"相反，是"**文字驱动、作者控镜、逐步递进的可操纵图示**"——每个可视化都嵌在论证链条中，配明确操作指引，读者被引导着一步步搭起心智模型。技术上全部手写原生 JS + WebGL，零框架依赖（moon.js 单文件 551KB）[7]。站点自我定位是 physics/math/engineering/stem——**元数据关键词不含 chemistry** [7]。
- **The Pudding 的生产栈**：SvelteKit + 自研 `Scrolly.svelte`（IntersectionObserver 原生实现，Svelte 5 runes）+ D3/可选 LayerCake + ArchieML/Google Docs 微型 CMS，开源模板 `the-pudding/svelte-starter` 活跃维护——scrollytelling 已有成熟生产脚手架 [8]。第二轮核验确认 LayerCake 并非模板默认依赖。
- **致命弱点即机会**：Distill 2021 年停刊，自证瓶颈是**每篇 100+ 小时投入、"科学 + 设计 + 工程"复合技能稀缺、工具链（Idyll 等）不成熟**——这种生产模式始终未能规模化复制 [9]。

### 教学法研究（CER）给出的设计铁律

- **Johnstone 三角**（1982–）：化学理解必须在**宏观（现象）—微观（粒子）—符号（公式/图）**三个表征层间转换，而学习者工作记忆容量有限，是化学难学的核心机制（Taber 2013, *CERP* 权威重审）[10]。
- 实证：整合三重表征的教学法（IMMSA）使学生的表征间"转译能力"从 fair（2.0）提升到 satisfactory（4.0）（ERIC EJ1205420）[10]。
- VR 教学元分析：平均效应量 ES = 0.64（中到大），但设备门槛高（ScienceDirect 2022）[10]。
- **推论**：相图恰好是 Johnstone 三角最尖锐的案例——它是纯"符号"表征（T-x 图上的一根线），而学生既看不到宏观（釜里到底发生了什么）也看不到微观（分子为什么分层）。**叙事可视化的本质任务就是把三角的三个顶点在一个屏幕里联动起来。**

### 中国国内生态

- 教育部自 2013 年起三轮国家级建设：虚拟仿真实验教学中心 → 示范性项目 → 一流课程（《大学化学》2022）[11]。
- 现状通病（《大学化学》2021 自述）：**碎片化、与理论知识脱节、难成完整教学体系**；多数高校以化工单元仿真为主，化学原理类偏少 [11]。天津大学平台 59 项实验、累计 4.8 万人次——体量可观但形态是"实验操作仿真"，不是"原理讲解" [11]。
- NOBOOK、矩道等商业方案面向中学实验演示，与大学原理教学不在一个生态位。

### 市场机会判断（第二轮校正）

化学可视化工具、二元 VLE WebApp、化学叙事教学与粒子—自由能联动都已有先行者，不能再声称“无人占据”。目前仍未发现同时满足以下四点的成熟项目：**面向大学化学原理、开放源码、作者控镜、宏观—微观—符号严格同步的交互长文**。这是基于已核验样本的产品定位，不是对全球不存在其他作品的事实断言。

必须诚实标注置信度：四条"某来源直接宣称存在空白"的声明在对抗验证中全部被否决。第二轮又找到多个直接反例，因此“组合型产品机会”仍是分析性推断（中等置信度），不能包装成学界已证明的市场空白。竞争优势最终要由成品质量、教学实验与开放生态证明。

## 第二部分：项目方案

### 一、愿景与定位

**一句话**：做化学界的 ciechanow.ski——以叙事驱动、计算可核验、遵循化学教育研究结论，打造大学化学原理中最值得被采用的开源交互式长文平台。

三个身份的叠加，缺一不可：

1. **内容**：一系列 Ciechanowski 式的交互长文（"故事"），每篇把一个大学化学核心概念从直觉讲到严格；
2. **引擎**：一个浏览器端实时运行的化学热力学/动力学计算内核（你现有 app.py 的进化形态）——保证故事里每张图都是活的、可被读者的手改变的；
3. **工具**：一套把"化学叙事文章"的创作成本从 100 小时降到 10 小时的开源创作框架——这是从"一个好网站"变成"一个生态"的关键，也是 Distill 之死告诉我们的教训 [9]。

**"全球第一好"的可操作定义**：在"大学化学原理的叙事式交互讲解"这个品类里，(a) 内容深度与美感对标 ciechanow.ski；(b) 教学法严格性超过所有现存化学可视化项目（显式实现 Johnstone 三角联动）；(c) 三年内成为该品类被引用/被链接最多的开源项目。

### 二、核心设计方法论："三角联动叙事"

每个"故事"的每一幕，屏幕上同时存在三个联动视图，对应 Johnstone 三角 [10]：

```
┌─────────────────────────────────────────────────┐
│  宏观视图            │  微观视图                 │
│  (蒸馏釜/烧杯的      │  (粒子模拟:分子逃逸、     │
│   写实渲染,液面、     │   碰撞、聚集——WebGL      │
│   沸腾、结晶动画)     │   粒子系统)              │
├─────────────────────┴───────────────────────────┤
│  符号视图                                        │
│  (相图/公式——即读者熟悉的 T-x 图,状态点在        │
│   三个视图间严格同步)                            │
└─────────────────────────────────────────────────┘
```

滚动叙事（scrollytelling）控制"镜头"：作者决定何时聚焦哪个视图、何时冻结参数、何时把控制权交给读者（"现在你来试：把外压降到 0.3 bar，看看共沸点去哪了"）。这直接实现 Distill 五效用中的"使系统可玩"与"降低认知负荷" [6]，同时用 Ciechanowski 的"作者控镜"避免 PhET 沙盒"给了自由却不知看哪"的问题 [7]。

**每个故事的标准结构**（借鉴 LearnChemE 三位一体 [5] 并内化）：

1. **钩子**：一个真实世界的反常现象（"为什么高原上煮不熟面条？""为什么蒸馏酒精永远到不了 100%？"）
2. **搭建**：逐幕引入变量，每幕只增加一个自由度（严格尊重工作记忆限制 [10]）
3. **顿悟**：核心图（相图）作为"故事的地图"完整登场——此刻读者已经从有来源的实验点亲手重建过它的关键区段
4. **反转/深化**：非理想性、共沸、分层——用理想模型的"失败"引出下一层理论
5. **自测**：嵌入式 ConcepTest 概念题（预测→操作→验证循环）
6. **纵深**：可折叠的严格推导层（KaTeX），供想深挖的读者

### 三、技术架构

```
┌──────────────────────────────────────────────────┐
│ 故事层  SvelteKit + MDsveX (Markdown里写交互组件)  │
│         Scrolly 滚动叙事 + LayerCake 2D图表        │
│         (直接站在 the-pudding/svelte-starter       │
│          的肩膀上 [8])                             │
├──────────────────────────────────────────────────┤
│ 视图层  三角联动组件库 (本项目核心资产)             │
│   · 宏观: Three.js 场景 (蒸馏釜、烧杯、结晶器)      │
│   · 微观: WebGL 粒子系统 (分子动力学风格演示)       │
│   · 符号: SVG/Canvas 相图组件 + KaTeX              │
│   · 同步总线: 单一状态store驱动三视图               │
├──────────────────────────────────────────────────┤
│ 引擎层  chem-engine (TypeScript, 独立npm包)        │
│   · Antoine / Margules / NRTL 活度模型             │
│   · Brent求根、凸包构造 (参照MIT Phase Diagram      │
│     Explorer的目标:快到60fps实时交互 [4])           │
│   · 从现有 app.py 移植,单元测试对照 Python 结果     │
│   · 远期研究: TDB/CALPHAD 浏览器或后端桥接 [3]     │
├──────────────────────────────────────────────────┤
│ 创作层  story-kit (第二年开源)                     │
│   · 故事模板、三角视图脚手架、ConcepTest组件        │
│   · 目标:化学教师+一个前端学生 = 10小时一篇故事     │
└──────────────────────────────────────────────────┘
```

**技术选型理由**：

- **放弃 Streamlit 作为最终形态**：Streamlit 每次交互走服务器往返，做不到滚动驱动的 60fps 叙事，也无法静态部署到 GitHub Pages/CDN 让全球零成本访问。但**保留 app.py 作为"物理正确性参考实现"**——每个 TS 引擎函数都要和它对数。
- **选 Svelte 而非 React**：The Pudding 已验证 Svelte 适合叙事可视化生产，且 `svelte-starter` 提供可借鉴的 Scrolly 模式 [8]；Svelte 编译产物小，符合"教育资源要在差网络下可用"。
- **不学 Ciechanowski 手写一切**：他是一个人十年磨一剑；我们要的是可复制的生产线，框架化是必然选择 [7][9]。
- **计算放浏览器端**：零服务器成本、离线可用、每个读者的操作即时响应——这是"图是活的"的物理前提。

### 五、开源与社区战略

- **代码 MIT**（跟随 pycalphad 的先例 [3]），**内容 CC BY 4.0**——刻意区别于 ChemTube3D 的 NC-SA：允许商业与非商业改编，只要求署名，传播即增长。
- **仓库结构**：`visual-chem`（故事站点）+ `chem-engine`（计算内核，独立发包，让其他教育项目也能用——成为基础设施）+ `story-kit`（创作框架）。
- **学术锚点**：每季内容整理投稿 *J. Chem. Educ.* 或 *CERP*（JSmol 相图 2009 一篇 Letter 被引至今 [4]，说明该期刊是此类工作的正确扩音器）；这也是"全球第一好"的可验证凭据。
- **合作对象优先级**：LearnChemE（ConcepTest 题库授权互换）、OSSCAR（Jupyter 生态互补 [2]）、国内《大学化学》期刊与虚拟仿真一流课程申报体系 [11]。

### 七、风险与对策

1. **最大风险：叙事创作成本**（Distill 之死的直接教训 [9]）。对策：先用三篇故事打磨出可复用的组件与模板，把边际成本压下来；story-kit 是战略防御工事，不是附属品。
2. **一人项目的持续性**。对策：每季度必须有可独立发布的里程碑；引擎与内容解耦，任何一部分停滞不拖垮全局。
3. **教学法自嗨**（做出来老师不用）。对策：每个故事上线前找 ≥5 名真实学生做出声思维测试；ConcepTest 答对率就是产品指标。
4. **直接竞品持续出现**。第二轮已补查 PhET/Labster/MolView/3Blue1Brown/JCE，并确认 2026 年已有 VLE WebApp。对策：每季冻结设计前更新一次竞品审计，差异化以可验证的叙事与三联动质量为准。

### 八、90 天行动清单
