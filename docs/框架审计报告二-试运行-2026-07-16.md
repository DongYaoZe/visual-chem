## 三、🔴 关键发现：部署链从未运转，且推送即失败

### 3.1 现状核实（三个独立证据）

1. `origin/main` 仍停在 `1cbfa9e`（旧 Streamlit 时代）——**`e115798` 从未推送**；
2. GitHub Actions API 返回 `"total_count": 0`——**两个 workflow 从未运行过一次**；
3. `https://dongyaoze.github.io/visual-chem/` 返回 **404**——站点从未部署。

也就是说：CI 绿灯、Pages 部署、生产 URL，目前全部只存在于文档里，没有一项被现实验证过。

### 3.2 品牌 404 测试：对 `vite preview` 确定性失败

`site.e2e.ts:157`（desktop + mobile 各失败一次）期望未知路由返回 `static/404.html` 品牌页（标题"这个状态点，不在图上"）。实测 Playwright 快照拿到的是：

```yaml
- heading "404" [level=1]
- paragraph: Not Found
- button "暂停动画"
```

这是 **SvelteKit 默认错误页 + 应用布局**。根因：`vite preview` 不是静态文件服务器——它加载 `.svelte-kit/output/server/manifest.js`，对未知路由**动态 SSR 渲染 `+error.svelte`**；只有 GitHub Pages 才会对缺失路径回送 `static/404.html`。我用 `curl` 复核了响应体：含"暂停动画"、不含"不在图上"，与快照一致。

**推论：这条测试在 CI 里同样必然失败。** 而 `deploy-pages.yml` 把 `npm run test:e2e` 放在 build job 里、上传产物之前——所以**一旦推送 main，部署将被这条测试永久阻塞**。第一轮说"ci.yml 与 deploy-pages.yml 重复跑全套验证"是小题；现在看它是致命题。

### 3.3 离线 Service Worker 测试：`ready` 30 秒超时

`site.e2e.ts:182` 在 `navigator.serviceWorker.ready` 上超时。两层原因：

- **环境层**：本机 8 GB 内存、commit charge 已用约 94%。构建期间三次出现 `FATAL ERROR: Committing semi space failed. Allocation failed - JavaScript heap out of memory`（堆仅 ~20 MB 时 OS 拒绝提交内存）。用 `NODE_OPTIONS="--max-old-space-size=768 --max-semi-space-size=8"` 可稳定通过。CI 已设 4096，不受影响，但**《落地进展》的本地验收命令应补上这一行说明**，否则下一个 8 GB 机器上的贡献者会以为构建坏了。
- **架构层（真问题）**：`service-worker.ts` 在 install 阶段一次性 `cache.addAll([...build, ...files, ...prerendered])`——实测 **81 个文件、约 1.8 MB**，其中 60+ 个是 KaTeX 字体的全部变体（woff/woff2/ttf × 每个字族）。任何一个请求失败整个 install 就失败，`ready` 永不解析；即便成功，`skipWaiting` + 版本化缓存名意味着**每次部署全量重新下载**。

### 3.4 修复方案（推荐顺序）

1. **新建 `web/scripts/serve-pages.mjs`（约 30 行）**：一个忠实模拟 GitHub Pages 语义的静态服务器——精确路径命中则回文件，未命中回 `404.html` + 状态码 404，支持 `BASE_PATH` 前缀。把 `playwright.config.ts` 的 `webServer.command` 换成 `npm run build && node scripts/serve-pages.mjs`。**收益不止修掉这条测试**：目前所有 e2e（包括通过的 20 个）跑在 SSR 渲染器上，而不是真正要部署的静态产物上；换掉之后，测的就是用户拿到的东西。`capture-audit.mjs` 也可指向它。
2. **SW 预缓存瘦身**：install 只预缓存应用壳（HTML + 当前故事的 JS/CSS + 正文用到的 woff2），KaTeX 字体与 OG 图走 fetch 事件的运行时缓存（现有 cache-then-network 分支已经能承担）。顺带解决"每次部署全量重下"。
3. 以上两项落地后，在本地完整跑一次 `validate + test:e2e` 全绿，**再推送 main**，看着 Actions 真实变绿、Pages 真实上线，才算闭环。

## 四、试运行看到的"格调"问题（截图证据）

### 4.1 混合液颜色发浑 —— OKLCH 项从理论升级为实证

场景 6 截图中，馏出液（y=0.618）和近共沸蒸馏瓶（x=0.899）的液体呈**脏褐灰色**——`DistillationApparatus.svelte` 的 sRGB 线性插值在暖橙（乙醇）与青蓝（水）之间穿过了低饱和度的泥区。乙醇富集本该读作"越来越清亮"，现在读作"越来越浑浊"，语义正好反了。第一轮的 OKLCH 建议现在有截图背书，优先级上调。

### 4.2 首页 hero 曲线也是手绘假货

第一轮只点名了故事页的 `M20 255C220 70 675 56 960 239`。本轮确认 **`HomePage.svelte:69-72` 同样是手编贝塞尔**（`M52 396C192 202…`、`M52 396C182 112…` 加两条装饰 orbit）。两处应一起换成 `buildTxyCurve` 预渲染的真实曲线——首页 hero 是全站第一眼，"每一条曲线都是算出来的"这句承诺应该从这里开始兑现。

### 4.3 λ 滑杆太素

场景 6 的"教学模型拨杆 λ"是裸 `<input type="range">`。建议：两端加刻度标签（`0 · 理想 Raoult` ↔ `1 · 校准 Margules`），中间可选一个 0.5 记号；这既是格调也是教学法——读者应该不看说明就知道两端各是什么世界。

### 4.4 移动端（390×844）基本成立，两处小瑕疵

- 右下角"暂停动画"悬浮钮与首页 hero 图形边缘轻微叠压；
- 场景 4 的粒子腔在窄卡里略显拥挤，宏观/微观图注被挤出首屏。
均为微调级，不阻塞。

### 4.5 值得点名的好

- 场景 4"亲手重建相图"在真实浏览器里的手感与叙事完全成立：按钮状态反馈（"这一组已加入"）、红色重建草稿线与灰色文献散点的层次、"粗虚线只是你依据已选数据画出的草图"的诚实图注——这一幕仍然是全站最好的交互，应按第一轮建议提炼为 story-kit 标准件；
- 状态徽章链（液 x / 气 y / 泡点 T）在桌面与移动端都清晰；
- axe 扫描 0 严重违规在两种视口下复核通过（e2e 中 4 条 a11y 测试全绿）。

| 《落地进展》原文 | 现实 | 改法 |
|------------------|------|------|
| （工程质量·已完成）"GitHub Actions 在 main 的 web/** 改动上验证并构建……部署到 Pages" | Actions 0 次运行、站点 404、代码未推送 | 移入"尚未完成"，或改写为"workflow 已编写，未经真实运行验收" |
| "Vitest 当前 12 项" | 实测 16 项 | 文档不写具体数字（必然过期），或由脚本生成 |
| "Playwright 当前 10 个桌面/移动场景" | 12 测试 × 2 项目 = 24 用例，其中 3 个失败 | 同上，且在修复 §三 前不应表述为全绿 |
