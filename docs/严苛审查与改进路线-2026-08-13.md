# VisualChem 严苛审查与改进路线

> 审查日期：2026-08-13  
> 审查对象：`D:\Documents\董耀择\dyz电子资料\5.化学\5.可视化`  
> 审查基准：不是“能运行的学生项目”，而是项目自己提出的“大学化学叙事可视化 / 化学界 ciechanow.ski / 可公开采用的高水平教育产品”标准。  
> 结论性质：产品、视觉、交互、教学与工程联合审查；分数为内部启发式评分，不是用户实验数据。

## 一、总评

VisualChem 已经越过了“技术演示”的门槛。它最难得的部分并不是 SvelteKit、Playwright 或漂亮的首页，而是已经形成了一套相当清醒的产品纪律：

- 计算状态驱动宏观、微观、符号三重表征；
- 测量、教学模型、解释性动画之间有证据边界；
- 数值内核有跨语言 golden points、实验数据和回归测试；
- 中英文内容、无障碍、GitHub Pages、离线和 SEO 都不是临时补丁；
- 第一篇“亲手从文献数据重建相图”的教学思路是真正有辨识度的。

但以项目自己设定的最高目标衡量，当前仍更像一个**工程非常扎实、视觉风格成熟的 Alpha 内容平台**，还不是一个“看一眼就知道它定义了新品类”的作品。

我给两套分数：

| 评估口径                               |     评分 | 判断                               |
| -------------------------------------- | -------: | ---------------------------------- |
| 作为个人/学生开源 Alpha                | 88 / 100 | 很强，远高于通常项目               |
| 作为 Ciechanowski / Distill 级标杆产品 | 64 / 100 | 还差一轮“少做内容、深做体验”的跃迁 |

最关键的判断是：**现在不应该继续用新增故事数量证明项目进展。** 十二篇已经足以证明生产能力。下一阶段应该冻结内容扩张，把 2–3 篇旗舰故事做成真正的标杆，并用真人学习测试证明它确实比普通图文、普通模拟更好。

## 三、最值得保留的优势

### 1. “图是算出来的”不是口号

这是项目的真正护城河。很多教育可视化只是把一个正确答案动画化，VisualChem 至少在核心故事中做到了状态、读数和曲线由计算内核生成。这个原则必须继续保留，而且以后所有视觉升级都不能牺牲它。

### 2. 第一篇的数据证据设计非常好

“让学生先用 Lai 2014 数据亲手重建相界，再看模型”比“先给模型曲线再解释”强很多。它把实验、模型和认知建模放在一个流程里，这比单纯做一个漂亮相图有教育价值。

### 3. 证据边界写得清楚

粒子位置不是分子动力学、Margules 不是实验回归、谱线亮度不冒充跃迁强度等措辞，是非常成熟的科学传播意识。不要为了更“炫”而把这部分删弱。

### 4. 自动化工程质量已经不错

Svelte check、Vitest、Playwright、axe、Pages 语义服务、双端视觉截图这些都说明项目已经有生产意识。当前问题主要不是“没有测试”，而是**测试覆盖的对象还没有追上产品变化速度**。

## 四、P0：下一阶段必须先解决的问题

## P0-1：冻结继续扩篇，先把 2–3 篇打磨成真正旗舰

### 问题

项目已经从 11 篇增长到 12 篇，最新提交包含 CO₂ 红外故事。但真人出声思维测试、教师审校、真实读屏器验收仍然是待办。

这意味着当前产品出现了典型风险：

> 内容生产速度 > 体验验证速度。

如果继续做第 13、14、15 篇，只会把尚未验证的交互模式复制得更广。

### 执行措施

未来 4–6 周暂停新增故事，集中打磨：

1. 《永远到不了的 100%》  
   作为“数据证据 + 相平衡 + 三重表征”的旗舰。

2. 《沸腾的地图》或《浓度的倒计时》  
   作为“概念直觉 + 连续变量”的旗舰。

3. 《氢原子为什么只发出几根线》或 CO₂ 红外  
   作为“结构与光谱”的视觉旗舰。

### 验收

每个旗舰至少做：

- 8–12 名目标学生出声思维；
- 3 题前测 + 3 题迁移后测；
- 记录完成时间、放弃点、误操作、错误解释；
- 至少 1 名物化或结构化学教师逐页审校；
- NVDA 或 VoiceOver 真实读屏器走查；
- Chrome / Safari / Firefox 至少人工检查一次。

只有完成这三篇的闭环，才恢复新增内容。

## P0-2：视觉已经“好看”，但还没有“不可替代”

### 观察

首页首屏有明显编辑设计感：大号衬线中文、米白底、橙色/青绿色、相图曲线、≈95.5% 数字锚点，第一印象是好的。

但进入多篇故事后，模板感迅速显现：

- 大标题占据大面积首屏；
- 左侧说明卡 + 右侧三联图；
- 宏观图常为浅灰线稿；
- 微观图常为“粒子框”；
- 符号图常为标准坐标图；
- 不同故事主要通过 accent color 和标题文字区分。

第三季三个 hero 尤其明显：大标题 + 一条淡色曲线 + 大量留白。单看优雅，连续看十几篇就会产生视觉疲劳。

### 核心判断

项目现在的“视觉系统”已经成熟，但“每篇故事独有的视觉发明”还不够。

Ciechanowski 式作品最强的地方不是统一设计系统，而是每篇都有一套只为那个概念发明的交互机械结构。

### 执行措施

对每个旗舰故事强制加入至少一个“不可复用的主视觉发明”：

- 乙醇蒸馏  
  让装置、气相富集、结线和相图之间出现连续的空间映射。比如从烧瓶里抽出一滴液体，视觉上直接“飞”到相图 x 点，再从蒸气滴落到 y 点，而不是三块面板同时静态刷新。

- 沸腾地图  
  用真实的压强腔/高原环境视觉，让外压线不是单独图上的一条线，而是和锅内气泡是否生存发生直接空间因果关联。

- 氢谱  
  把“能级下降 → 光子飞出 → 光栅分光 → 光谱线上出现位置”做成一条连续动作，而不是三个相邻区域各自更新。

- CO₂ 红外  
  把分子振动、偶极矩箭头和吸收谱带做成单一视觉因果链。对称伸缩时偶极箭头抵消，反对称伸缩时箭头周期变化，谱线上同步出现/消失吸收。

### 验收

要求不看正文，只看 10 秒动画录屏，测试者也能回答：

- 哪个变量变了？
- 为什么右边的图跟着变？
- 三个表征之间是什么因果关系？

回答不出来，就说明“三重表征”仍然只是并排，而没有真正融合。

## P0-3：移动端的滚动叙事节奏需要重做

### 观察

390×844 下：

- 首页视觉能成立，但 ≈95.5% 主视觉被推到首屏下部，只露出一部分；
- 第一篇 hero 的大标题占据大量纵向空间，交互钩子仍要继续滚动才能真正开始；
- 滚动故事中 sticky 图形占据上方约 35–45% 视口，正文卡片只能露出几行；
- 截图中正文经常从段落中间开始显示，读者容易失去“现在讲到哪里”的上下文；
- 右下角全局“暂停动画”悬浮控件会侵入故事控制区附近。

自动化没有横向溢出并不等于移动阅读体验好。

### 执行措施

移动端不要简单缩小桌面 scrollytelling。建议改为明确的“二态阅读”：

**模式 A：文本优先**

- 图形压缩为 120–160px 高的状态摘要；
- 正文完整占据主要视口；
- 点“展开图”进入模式 B。

**模式 B：图形优先**

- 图形占 60–70vh；
- 当前幕只有 1–2 句结论和一个操作；
- 向下继续时自动回到文本优先。

同时：

- hero 手机端标题最大字号下调约 12–18%；
- 不把完整曲线塞在 hero 底部，改成更明确的局部视觉钩子；
- “暂停动画”移动到 header 菜单或安全区，不悬浮覆盖内容；
- 所有 slider 在 390px 下保证标签、读数、轨道和说明不争夺一行。

### 验收

在 390×844 和 320×568 下逐幕录屏，要求：

- 任意时刻至少能看到一条完整因果句；
- 当前操作控件不被固定按钮遮挡；
- 用户不用来回滚动才能同时理解“操作”和“结果”。

## P0-4：真人学习证据必须从“待办”变成产品门禁

当前文档已经意识到这点，但执行优先级仍然偏低。

### 建议门禁

每篇故事不再以“测试全绿”作为完成定义，而是增加：

- **概念迁移**：后测题不是原句复述，而是换情境；
- **解释质量**：至少 70% 学生能用自己的话给出核心因果链；
- **交互可发现性**：关键交互无需口头提示完成率 ≥ 80%；
- **卡点率**：任一关键幕超过 25% 学生停滞，应重做；
- **错觉监测**：重点记录“看完以后更自信但解释更错”的情况。

数字可以在第一轮测试后调整，但必须有门槛。

## 五、P1：很高收益的产品与视觉改进

## P1-1：首页从“故事列表”升级成“化学知识地图”

当前 12 篇按 Season 01–04 纵向排列，信息清楚，但视觉上更像目录页。

缺少：

- 概念依赖；
- 学习路径；
- 难度；
- 先修；
- “我现在适合从哪里开始”。

### 建议

首页保留当前 editorial hero，但故事目录改成可视化知识地图：

- 横轴：宏观现象 → 热力学 → 动力学 → 结构与光谱；
- 节点：12 篇故事；
- 连线：
  - “前置”
  - “回扣”
  - “同一方程”
  - “同一实验方法”
- 每篇显示：
  - 预计时间
  - 难度
  - 先修
  - 核心变量
  - 主要表征
- 提供三条入口：
  - 第一次学物化
  - 期末复习
  - 只想看最震撼的三个故事

这会让“平台”感显著强于“12 篇文章的列表”。

  - 下一篇

## P1-3：减少“模板化三联卡”，增加镜头变化

当前很多关键幕依然同时展示三幅图。虽然项目有 focus/降噪逻辑，但视觉截图仍常呈现固定三分栏。

建议每幕明确只有一个“主角”：

- 幕 A：宏观 70%，微观和符号退到角落；
- 幕 B：宏观局部 morph 成微观；
- 幕 C：微观轨迹直接变成符号曲线；
- 幕 D：三者一起出现做总括。

这样才能真正利用“作者控镜”，而不是把 Johnstone 三角永久做成 dashboard。

---

## P1-4：宏观与微观视觉需要摆脱“灰色教学示意图感”

目前宏观装置大量采用浅灰描边，科学清楚，但情绪和物质感不足。

建议不要追求拟真 3D，而是升级为“有物质感的二维科学插画”：

- 玻璃折射、液面、蒸气、辉光、金属、电极、晶体等采用有限但明确的材质语言；
- 动画只保留能解释因果的部分；
- 关键物质颜色跨宏观、微观、符号视图保持一致；
- 相同变量使用相同视觉 token，比如温度始终对应同一色温尺度，浓度始终对应同一饱和度或填充比例。

视觉效果会比继续增加阴影或渐变更高级。

---

## P1-5：首屏需要更快给出“可玩性”

多个故事 hero 非常漂亮，但主要是标题和一句话，真正交互要继续滚动。

建议每个 hero 都有一个 5–10 秒可玩钩子：

- 动力学：直接拖时间，看到浓度和气泡变化；
- 催化：点“加催化剂”，两条能垒即时切换；
- 氢谱：点一条跃迁，屏幕出现一根谱线；
- CO₂：点三个振动模式，立刻看到“能不能吸收”。

让用户在 15 秒内得到第一次“我操控了一个真实关系”的反馈。

---

## P1-6：第一篇的“16 组实验数据重建”交互可更聪明

当前流程是 slider 选样品 → 点加入 → 重复至少 5 次。

教学目标正确，但操作形式略机械，移动端尤其费。

建议改成：

- 16 个样品点直接以小型数据条 / 点阵显示；
- 点击任意一个样品，圆、三角和结线同时落图；
- 选中 5 个后自动提示“你已经覆盖了低/中/高组成吗？”
- 如果学生只选一侧，系统提示实验设计偏置，而不是只计数。

这样能把“选数据”从 UI 操作升级成“采样策略”的学习任务。

## P1-10：生产视觉审计的 BASE_PATH 流程应一键化

文档要求：

1. `BASE_PATH=/visual-chem` build；
2. serve；
3. `VISUAL_CHEM_ORIGIN=http://127.0.0.1:4173/visual-chem`；
4. audit。

本轮现有 build 实际是根路径，因此第一次按文档跑 audit 时页面返回 404，直到改为根 origin 才成功。

这不是产品 bug，但说明审计流程容易被“build 是哪个 base path”这个隐式状态破坏。

### 建议

新增单命令：

```bash
npm run audit:production
```

脚本自己完成：

- 清理旧 build；
- 固定 BASE_PATH；
- build；
- 启动临时 server；
- 等待端口；
- 执行 visual audit；
- 结束 server；
- 输出 screenshot index。

不要让操作者手工维护两个环境变量的一致性。

## 七、P2：可以随后推进的改进

### 1. 主题色 token 化

CO₂ 等故事存在直接写入 `#357c9d`、`#17242a` 一类颜色。建议每篇只声明 theme token，由共享组件消费，避免对比度和视觉风格漂移。

### 2. 增加性能预算

当前工程质量记录很多，但缺少面向用户的性能预算。

建议 CI 增加：

- 首屏 JS gzip 预算；
- LCP；
- CLS；
- INP；
- 低端 Android 4× CPU slowdown 的首屏可交互时间；
- 断网后已访问故事可用性。

### 3. 数学公式做真实读屏器专项

Axe 绿灯不代表 KaTeX 朗读自然。需要真实 NVDA / VoiceOver 检查：

- 是否重复朗读视觉 HTML 与 MathML；
- 分数、上下标、希腊字母是否可理解；
- 长公式是否有简短解释文本。

### 4. 加入学习进度，但不要游戏化

可以记录本地完成状态：

- 已读；
- 做过预测；
- 完成 concept check；
- 进入 sandbox。

不要做积分、连续签到一类弱相关机制。

## 十、最终判断

这个项目现在最危险的方向，是继续证明“我还能再做一篇”。

这一点已经证明完了。

下一阶段真正决定 VisualChem 上限的问题是：

> 能不能让一个没有参与开发的学生，在手机或电脑上独立完成一篇故事，明显感到“我第一次真正看懂了这个关系”，并且在换一个题目以后仍然解释得出来。

工程层已经足够支撑这个目标。当前应该把资源从“新增功能与新增故事”转到：

**旗舰视觉发明 → 移动端节奏 → 真人学习验证 → 导航与知识地图 → 生产流程收敛。**

如果这五件事完成，VisualChem 才会从“很强的个人项目”进入“有机会成为标杆教学作品”的阶段。
