## 〇、总评——先说做对了什么

以下几点是这个项目的灵魂，**任何后续重构都不得破坏**：

1. **证据分层是全项目最有格调的决定。** `ethanol-water-lai-2014.ts` 带 NIST ThermoML 的 DOI、数据集编号、MD5/SHA256 校验和、转换记录（"无插值、无平滑"）；Kamihama 2012 标记为 `independent-validation-only` 拒绝与校准集混合；模型卡里"这幅图知道什么，又不知道什么"四段式声明。这是 Distill 级别的知识诚实，全球化学教育可视化项目里未见第二家。
2. **发现并公开承认旧 `app.py` 的定量错误**（旧 Margules A=1.6 给出 89.0 wt% 共沸 vs 实验 95.4–95.6 wt%），并把修正过程写进模型卡——这正是"计算真实"的兑现。
3. **第二轮调研纠正了蓝图自己的错误**（ChemTube3D 实为 CC BY-NC-SA 而非 NC-ND；JCE 2026 已有二元 VLE WebApp），并据此放弃一切"全球首个"式宣传，改为可验证的产品特性定位。完全正确。
4. 跨语言 golden test（SciPy `brentq` 1e-14 → Vitest 对照到 7 位小数）、Playwright + axe 全链路、杠杆规则闭合测试、"级联不穿越共沸点"测试——工程质量是真实的。
5. 视觉系统（纸面米色 + 墨绿 + 乙醇橙/水青、衬线大标题 + mono 数据标签）有统一的编辑气质，摆脱了 Streamlit 控制面板语言。

## 一、红线：必须立即处理

### 1.1 删除 `kits/claude_auto_allow.py`

这是一个**用屏幕像素识别自动点击 AI 代理权限确认框的脚本**。问题：

- 与化学可视化项目**毫无关系**，却被提交进了公开仓库的 `main`；

- 它含有作者本机工作流的痕迹（Antigravity 窗口标题匹配），属于个人工具，不属于产品仓库。

**行动**：`git rm kits/claude_auto_allow.py`，若 `kits/` 因此为空则一并删除；此类个人自动化脚本应放在仓库之外。（历史提交中已存在，如在意可评估是否需要改写历史，但至少 HEAD 必须干净。）

### 1.2 三方位置耦合：内容、镜头、交互靠数组下标对齐

当前一幕戏的定义被拆在三处，仅靠**下标**隐式对齐：

- `content/stories/ethanol-distillation/zh-CN.ts` 与 `en.ts` 的 `scenes[]`（文本，各 9 项）

**行动**（这同时就是 story-kit 的雏形，一举两得）：

## 三、架构与优雅性

### 3.1 "同步总线"要真的存在：热力学状态只算一次

现状：`TriView.svelte:54` 算一次 `simpleDistillationStages`，`TxyDiagram.svelte:52` 用相同入参**再算一次**；`findAzeotrope` 同样在两处各算一遍。三视图不是被"同一个状态"驱动，而是被"相同的输入分别驱动"——结果恰好一致，但这是巧合式正确，且浪费计算。

**行动**：在 TriView（或独立的 `story-state.svelte.ts`）里派生一个完整的 `ThermoFrame` 对象：

```ts
interface ThermoFrame {
  current: EquilibriumPoint;
  stages: DistillationStage[];
  curve: EquilibriumPoint[];
  azeotrope: AzeotropePoint | null;
}
```

三个子组件全部降级为**纯展示组件**（props in, SVG out，零计算）。这才配得上"一个状态源驱动三幅图"的文档表述，也是 story-kit 里最有复用价值的抽象。

### 3.2 引擎的乙醇—水硬编码：第二篇故事的隐形墙

- `chem/types.ts:9`：`Component.id: 'ethanol' | 'water'`——类型层面把引擎焊死在一个体系上；
- `TxyDiagram`/`TriView` 直接 import `ETHANOL_WATER` 和 `ETHANOL_WATER_LAI_2014` 作默认值——组件与具体体系、具体数据集绑死；
- 引擎函数虽有 `system` 参数（好），但 `interactionScale` 这个纯教学用的 λ 拨杆混进了引擎签名——它不是热力学概念，是叙事概念。

**行动**：`Component.id: string`；组件的 `system`/`experimentalData` 一律显式传入，不设全局默认；把 λ 形变从引擎移到调用侧（`scaleInteraction(system, λ): BinarySystem` 一个纯函数即可）。做完这三件事，`chem/` 就自然具备独立发包资格。

### 3.3 拆解 1554 行的故事组件

`EthanolDistillationStory.svelte` 承担了：滚动侦测、九幕状态机、六种交互控件、短屏对话框焦点管理、分子筛物料衡算、全部版式。建议拆为：

- `Scrolly.svelte`——IntersectionObserver + `data-scene-index` 归属（对齐 The Pudding 的心智模型，向上滚动可逆已实现，保持）；
- `StoryStage.svelte`——短屏弹层 + 焦点管理（这段焦点恢复代码写得不错，值得复用）；
- 交互控件按 §1.2 的 `interaction` 枚举做成小组件注册表；
- 分子筛一节（`escape`）本身就是独立场景组件的好样板。

拆完后第二篇故事的边际成本才是蓝图承诺的"10 小时"量级。

## 四、数值内核

### 4.1 二分法 → Brent

`root.ts` 用纯二分（tol 1e-9，最多 120 次迭代）。正确但慢：λ 滑杆每次 input 都要重建 101 点 T-x-y 曲线，每点一次求根、每次求根 ~30–60 次 `totalPressureAt`（含 4 次 `10**x`/`exp`）。桌面无感，低端手机上连续拖动会掉帧。Brent（反二次插值+割线+二分混合）在同样保证下典型 8–12 次迭代收敛，**且 Python 参考实现用的就是 `brentq`——TS 侧同算法对数在方法论上更漂亮**。~60 行代码，收益 3–5×。

其余数值层评价：`dewPointAt` 对 `y(x)` 反解在乙醇—水的单调性下是安全的；`flashAt` 的杠杆闭合、共沸 5e-4 容差处理干净；`findInteriorRoots` 在三处用了 160/240/500 三个不一致的采样密度——统一成常量并注释依据。

### 4.2 Antoine 有效范围形同虚设

`AntoineConstants.validRangeC` 被记录（乙醇 [0, 78.3]）却从不检查——而稀乙醇泡点计算会在 ~96 °C 处评估乙醇的 Antoine 方程，**超出标注范围 18 K**。教学上这个外推可接受（也是常规做法），但一个把"证据边界"当卖点的项目，应该：要么在引擎里对超范围评估记录一个 `extrapolated: true` 标志并在模型卡里写明"稀醇区乙醇蒸气压为 Antoine 外推"，要么删掉这个从不使用的字段。**记录了却不执行的约束比没有约束更糟。**

## 五、设计与格调

### 5.1 两条"假曲线"违反了项目的第一性原则

- 故事 hero 的 SVG（`EthanolDistillationStory.svelte:266`）：`M20 255C220 70 675 56 960 239` 是手绘贝塞尔，旁边却标注"约 95.5 wt% · 常压实验"——**手绘装饰配真实数据标签，这是全项目唯一一处口是心非**；
- 首页 hero 的 `orbit/curve` 路径同理。

引擎就在手边：预渲染 `buildTxyCurve` 输出成路径字符串（构建时算好即可，不必运行时算），让第一屏就是真的泡点/露点线。当读者后来在第 4 幕亲手重建出同一条曲线时，会认出它——这是叙事上的伏笔回收，成本半小时。

### 5.2 颜色插值

`DistillationApparatus.svelte:21` 的 `mixtureColor` 在 sRGB 空间线性插值 teal→orange，中段会经过一段发灰的浑浊区。改用 OKLCH 插值（现代浏览器 `color-mix(in oklch, ...)` 原生支持，或 10 行手写转换），混合物颜色会在整个组成域里保持"透亮的液体感"。小改动，大质感。

### 5.3 值得保持的

粒子舱的自我声明（"位置与运动为示意，不冒充分子动力学"）、图例不只靠颜色区分（实线/虚线 + 圆/三角）、`prefers-reduced-motion` 全局处理、`AnimationToggle`、44px 触控目标——这些细节都对。别在重构中弄丢。

## 六、教学法与文案

1. **"理想"一词过载**（第 0 幕）："给这座'理想平衡塔'继续加级"——此处"理想"指*理想化的平衡级*（每级充分平衡），但第 5/6 幕里"理想"指*理想溶液*（Raoult, λ=0）。而第 0 幕的级联实际跑在 λ=1 的非理想模型上（这是对的，否则钩子里的"停在 0.895"不会发生）。同一个词在一篇文章里指两个概念且与模型状态交叉，是首篇最大的概念隐患。建议：第 0 幕改为"这座每级都充分平衡的塔"，把"理想"一词严格保留给溶液模型。
2. 第 4 幕"亲手重建相图"是整篇最好的一幕——它把 Johnstone 三角的符号顶点从"被展示"变成"被建造"，比蓝图原设想更进一步。第二篇故事应把这个"从数据重建图"的模式固化为 story-kit 的标准交互之一。
3. 结线一幕（第 3 幕）文本讲了"完全冷凝只改变相态"，但微观视图此刻没有对应的"冷凝"视觉事件——三角联动在这一瞬间只有两角在动。可以在时间线上加一个冷凝闪帧，低优先级。
